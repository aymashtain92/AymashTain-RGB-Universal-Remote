## 1. What this project is

Windows desktop app for controlling cheap BLE LED strips that use the **MR Star app** and related clone controllers.

Three physical strips:

- `41:42:59:F1:C8:68`
- `41:42:43:E7:8B:F6`
- `41:42:F9:D7:45:B0`

They advertise as `GATT--DEMO` and use:

- Service: `00002022-0000-1000-8000-00805f9b34fb`
- Write characteristic: `0000fff3-0000-1000-8000-00805f9b34fb`

This project is a **package**, not a single `main.py`. The real code is inside the `aymashtain/` folder.

## 4. What already works (do not remove)

- **Serialized BLE queue per device** in `ble/manager.py`. Every device
  owns its own `asyncio.Queue` and worker task. Colour and brightness
  cannot interleave.
- **Ordered colour -> brightness** in `BleManager.set_color()`. Colour
  first, then brightness.
- **Session logger** writes `.log`, `.json`, `.csv` on every event.
- **Auto-save on close** via `closeEvent` -> `session_logger.flush_json()`.
- **Auto-reconnect** with backoff.
- **9 tabs** - Connect, Remote, Music & Media, Sweep, Camera, Console,
  Lab, Events, Options.
- **Camera sampling** with white-contamination scoring.
- **Sweep tab** with optional camera verification.
- **Emergency stop** via Esc key and Control menu.
- **PyInstaller spec** with Qt module exclusions.
- **3/3 strips connect, 54 frames sent, 0 failed** (verified from running
  app).
- **Developer-tools lock** hides Lab tab for end users.

Do **not** replace this with a flat single-file `main.py`. The package is
better.

## 5. Confirmed protocol

### Colour

```text
BC 04 06 HH HH SS SS 00 00 55
```

Hue 0-359, saturation 0-1000, reserved `0000`.

Examples:

```text
Red:   BC0406000003E8000055
Green: BC0406007803E8000055
Blue:  BC040600F003E8000055
```

### Brightness (separate command)

```text
BC 05 06 BB BB 00 00 00 00 55
```

0-1024. Examples:

```text
100% = BC0506040000000055
75%  = BC0506030000000055
50%  = BC0506020000000055
25%  = BC0506010000000055
0%   = BC0506000000000055
```

### Power

```text
ON  = BC01010155
OFF = BC01010055
```

### Captured static / exit dynamic mode

```text
BC04010055
```

### Captured Scroll macro (setup + 25 frames + end)

See `protocol/mrstar.py` -> `SCROLL_MACRO`. Do not modify.

### Classic Magic Home (separate family)

```text
ON  = CC2333
OFF = CC2433
RGB = 56RRGGBB00F0AA
```

## 8. Golden rules for any AI reading this

1. Never mix MR Star BC commands with Classic 56/CC commands.
2. Never put brightness inside the colour frame.
3. Never use `FFFF` as a white field.
4. Never use `asyncio.create_task()` to fire colour and brightness in
   parallel.
5. Keep the per-device serialized queue in `BleManager`. Do not remove
   it.
6. Never run Music Sync or Scroll during static colour tests.
7. Never claim the app can read actual LED state over BLE.
8. Camera stays local-only. No uploads.
9. Python is 3.14.7. Do not use `py -3.12`.
10. Provide full replacement files, not partial patches.
11. Always run `python -m py_compile .\file.py` after replacement.
12. Do not auto-elevate to administrator.
13. Do not overwrite logs.
14. Preserve captured Scroll frames exactly.
15. Always run `python -m pytest -q` after touching any package
    `__init__.py`.
16. This project is free forever. No ads. No telemetry.

## 9. Hand-off tool

**`make_handoff.bat`** in the project root, double-clicked, builds a
numbered zip in `handoff\` containing a **flat, single-folder snapshot**
of the project plus the merged sync pack docs.

### What the bundle looks like

One folder. **No subdirectories.** Every file has a unique name.

- `HANDOFF_README.txt` — top of the bundle, tells the next AI where to
  start.
- `00_PROJECT_MASTER_DOCS.md` — merged from `00_MASTER_SUMMARY`,
  `02_UNIVERSAL_AI_PROMPT`, `05_DEVELOPER_README`, `07_HOW_TO_USE_AI_SYNC`.
- `01_WORKFLOW_AND_TODO.md` — merged from `01_WORKFLOW`,
  `03_TODO_USER_AND_AI`, `04_AI_ERRORS_ONLY`.
- `02_CURRENT_CHAT.md` — the old `06`.
- `_package_init_exports.md` — the five tiny sub-package `__init__.py`
  files merged into one reference doc (they were re-export shims; too
  small to be worth five separate files).
- Every source file, flattened: `aymashtain/ui/tabs/remote_tab.py`
  becomes `aymashtain__ui__tabs__remote_tab.py`.
- Every text file starts with an `# Original Path:` header (or an HTML
  comment header for markdown) so any AI knows where it belongs.

### Target size

**32 files** — verified by dry run. That leaves **18 free slots** under
DeepSeek's 50-file upload cap so the user can still attach screenshots.

### What is excluded

- `.gitignore`, `pyproject.toml`, `requirements.txt`, `.spec`,
  `README.md`, `CREDITS.md`, `LICENSE.txt` — not needed by the AI.
- `tests/`, `assets/`, `build/`, `dist/`, `.venv/`, `.git/`,
  `__pycache__/`, `.pytest_cache/`.
- `.db` files (private profiles and buttons).
- Session logs, exported `events.csv` / `events.json`, `test.txt`.
- The `handoff/` folder itself (so bundles never nest).
- All `AI_*` helper files (`AI_CONTEXT.md`, `AI_NOTES.md`,
  `AI_SESSIONS.md`, `AI_BRIEF.md`, `AI_BACKLOG.md`, `PROJECT.md`,
  `ai_sync.py`).

### How to run it

```powershell
# Build the zip:
python make_handoff.py

# Or list the files only, without creating a zip:
python make_handoff.py --dry-run
```

Or double-click `make_handoff.bat`, which runs the builder, prints the
file count, and opens the `handoff\` folder when it's done.

### Numbering

Every run increments the number: `handoff_001.zip`, `handoff_002.zip`,
and so on. **Nothing is ever overwritten or deleted.**

### How the user sends it

1. Unzip the newest `handoff\handoff_NNN.zip` anywhere.
2. Open a fresh AI chat.
3. Drag the **unzipped folder** (the flat one, not the zip) into the
   chat.
4. Paste the prompt from the top of `00_PROJECT_MASTER_DOCS.md`.

The bundle's `HANDOFF_README.txt` also tells the next AI what to read
first in case the user forgets to paste the prompt.

### End-of-session ritual

`AI_SYNC_PACK/08_End_Chat.md` is a separate reusable prompt the user
pastes at the end of any AI session. It tells the AI to:

- Append a new session section to `06_CURRENT_CHAT.md`.
- Tick / move items in `03_TODO_USER_AND_AI.md`.
- Add a dated entry to `01_WORKFLOW.md`.
- Add new rules to `04_AI_ERRORS_ONLY.md` **only** if a mistake was
  made.
- Skip the other sync-pack files unless their trigger conditions apply.
- Deliver **one file at a time**, waiting for the user to say "next"
  between files.
- Print a short summary at the end.

`08_End_Chat.md` lives only on the user's PC. It is **not** merged into
the flat bundle.

See `07_HOW_TO_USE_AI_SYNC.md` for the beginner walkthrough.
